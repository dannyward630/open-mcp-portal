# Open MCP Portal v0.2.1

A small release after [v0.2.0](v0.2.0.md): a better **Test connection**, a cap on open client registration, and the project's first real Kubernetes smoke test. There is no migration and nothing you must change to upgrade.

## What changed

- **Test connection exercises the identity token.** A manual Test now sends the identity token of the editor who pressed the button (when the server's **Send identity token** is on), the way a real call would. If the server answers `401` or `403` with the token and accepts the same request without it, the Test fails with a message that says so: *turn off Send identity token for this server, or have the server accept it.* Scheduled health checks and refresh still send no token. The token's claims are the editor's own, with the gateway `omp:test` and the client `Test connection` (decision 61). **What this does not catch:** a server that accepts the request and rejects the token only when a tool runs, such as DeepWiki's public endpoint (HTTP 200 with an error result), still passes Test. For those, turn the switch off for servers outside your company. The switch's help text now says what is sent, and the troubleshooting page covers the case.
- **A cap on dynamically registered clients.** `POST /oauth/register` is open by design, so `OAUTH_MAX_REGISTERED_CLIENTS` (default `1000`, `0` for no cap) bounds the clients registered and used within the last 30 days. Over the cap the portal answers `503 temporarily_unavailable` and tells the person to ask the administrator. Clients that identify themselves with a Client ID Metadata Document, such as Claude Code, are not counted. This is threat-model idea H-4.
- **A Kubernetes smoke test.** `make k8s-smoke` builds the images, creates a three-node `kind` cluster, applies the Kustomize base and checks, in about two minutes: the migrate init container and `doctor`; two replicas on different nodes; sign-in, a team, a server, a gateway and a key through the API; tool calls through `/mcp` in **both protocol eras**; a rolling update and a pod deletion under load with no failed request; the SIGTERM drain; and the PodDisruptionBudget. With `SMOKE_CNI=calico` it also checks that the NetworkPolicies block what they should. A CI workflow runs it on changes to `deploy/**`, weekly and on demand. [Smoke test](../deploy.md#smoke-test) says what it proves and what it does not.
- **Dependencies:** `kin-openapi` 0.151.0, `go-jose` 4.1.6, `goose` 3.29.0, and the web group (React 19.3.1 and others). `govulncheck` and `npm audit` report nothing.
- **Repository:** a stray `web/node_modules` symlink that v0.2.0 committed by mistake is no longer tracked. Issue forms (bug, client compatibility report, feature request) and GitHub Discussions are in place, and the documentation has a [client compatibility](https://docs.omp.bitop.dev/docs/use/client-compatibility) page.

## Upgrading

1. Pin the new image (verify its signature first, see [Verifying the images](v0.1.0.md#verifying-the-images)); the init container applies migrations, and there are none in this release.
2. If more than 1000 clients registered themselves in the last 30 days, new registrations are refused until some go unused or you raise `OAUTH_MAX_REGISTERED_CLIENTS`. Most installs are nowhere near that.
3. Editors who press **Test connection** now cause the server to receive their identity token (name, email, team slugs), as real calls from them already do. Turn **Send identity token** off for a server that shouldn't.

## Verification

- Go tests with the race detector against PostgreSQL, the web tests, the route and authorization-matrix tests, and `make k8s-validate` and `actionlint`.
- `make k8s-smoke` passed on the release tree: 30 assertions on the default `kindnet` CNI, 37 with Calico.
- Claude Code 2.1.280 was run against a real deployment of v0.2.0, over OAuth and an API key, on the 2026-07-28 revision ([status](../status.md)); the database of that deployment has continuous backups and a tested restore.

## Known limitations

Carried over from v0.2.0 unless marked new:

- **Not run with a real VS Code or Cursor.** They are the most useful reports to send: the [client compatibility page](https://docs.omp.bitop.dev/docs/use/client-compatibility) has a ten-minute checklist.
- **A real Google or Microsoft delegated-credentials provider** has not been run (only GitHub has, end to end). Real SMTP over TLS and a real Slack webhook have not been run either.
- **The smoke test (new)** does not test NetworkPolicy on its default CNI, ingress and TLS, OIDC, zone spreading, upgrades or restores; and with its development sign-in the portal allows private HTTP upstreams, so it can't prove the internal-network allowlist.
- **A server that refuses an Authorization header only when a tool runs** passes Test (see above).
- **Open threat-model ideas:** see the status table in [the threat model](../threat-model.md#9-hardening-ideas-not-findings).
- Remote servers only (no stdio); development software that has not run in production.
